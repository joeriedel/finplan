# finplan

finplan is a personal financial planner for one user. It is a Linux desktop app written in Go, drawing its UI with Dear ImGui and ImPlot (via cimgui-go) on SDL3, as a native Wayland client. It shows a tabbed application shell with working Graph, Projections, Assets, Accounts and Budget tabs over the record in its database (an invented family record with `--demo`); the other tabs are placeholders. The UI uses a dark theme and the bundled Inter font.

The data model, projection engine and planned features are described in [docs/design.md](docs/design.md). The model and a projection engine, which withholds, computes and reconciles taxes with the rules package, exist as standalone Go packages, `internal/model` and `internal/engine` and the Graph tab draws from them. A storage layer, `internal/store`, saves and loads the record to SQLite, and the app uses it.

## Prerequisites

- podman, used to build and test inside a Fedora 43 container (no Go toolchain is needed on the host)
- SDL3 on the host (`libSDL3.so.0`, Fedora package `SDL3`) to run the app

## Build

    scripts/build.sh

This builds the container image on first use (and whenever the `Containerfile` changes) and produces `bin/finplan`.

## Test

    scripts/test.sh

Runs a gofmt check, `go vet` and `go test -timeout 20m` in the container. Containers run under `podman run --timeout` (`FINPLAN_CONTAINER_TIMEOUT`, default 1800 s) and the image build under `timeout` (`FINPLAN_BUILD_TIMEOUT`, default 3600 s). The tests include a headless GUI smoke test (`cmd/finplan/smoke_test.go`): it builds the binary and, on the demo data and SDL's offscreen video driver, takes a screenshot of every tab (of the Checking account selected with `--select`, plain and with `--open ledger`, of the Assets tab with Net worth selected, of the Graph with Monte Carlo bands on the Net worth line under Base, of the Graph's breakdown panel (`breakdown-line`, `breakdown-interval`, `breakdown-expand`) and of each `--open` state: the pickers and the forms behind them, the Projections new budget item form and a Budget item's editor). Every case runs with `--check-ids`, so a widget ID conflict fails the test, and each case has a 30 s limit. It fails on a non-zero exit, panic output, a PNG of the wrong size or a single-colour image, and also checks the errors for bad screenshot arguments and that a SIGINT to a running `--demo` window leaves no demo folder behind. `scripts/test.sh` sets `FINPLAN_SMOKE_OUT` so the screenshots are kept in `test-output/screenshots/` (ignored by git); without it they go to a temporary folder. The container installs Mesa's software OpenGL drivers, so the smoke test needs no display and runs in CI.

## Run

    bin/finplan [--demo]

With `--demo` the app runs against a temporary database seeded from the invented family data and the family view presets; it is removed on exit, including on SIGINT and SIGTERM, and the window title is "finplan (demo)". The demo folder is `finplan-demo-*` in the system temp folder, holding `demo.db` and an `owner.pid` file with the PID of the running process; when a demo starts, `finplan-demo-*` folders whose `owner.pid` names a process that is no longer running (for example after a kill) are removed, while folders with a live owner or without a readable `owner.pid` are left alone. Without it the app uses `$XDG_DATA_HOME/finplan/finplan.db` (only when `XDG_DATA_HOME` is an absolute path) or else `~/.local/share/finplan/finplan.db`; the folder is created with mode 0700. An empty database shows a hint on the Graph tab. A database whose stored today is unset (0, or no record document) loads with today set to the current date each time and keeps it unset when saved; a stored date, like the demo's fixed one, is used as it is.

File > Backup... opens a save dialog (`.db` filter, default name `finplan-backup-YYYY-MM-DD.db`) and writes a consistent copy of the database. It refuses to overwrite the open database itself.

Drag to pan and scroll to zoom the plot (the y axis refits to the lines visible in the new x range; dragging y alone does not refit). The toolbar has a Projection dropdown and range buttons (1Y, 5Y, 10Y, 30Y, All). In the line list, checkboxes toggle a line, the S button solos it (only soloed lines are drawn; a "Solo: N · Clear" chip or Ctrl-click on any S button clears all solos, and the checkboxes are left as they were), "+ Add" adds one, and rows can be pinned to a projection, recoloured and removed (the solo, pin and remove buttons show while the row is hovered). The Bands section shades the gap between two lines (optionally hatched, with the gap at the cursor in the tooltip, also in today's dollars), and the View preset section saves and restores the lines, bands and date range (presets are saved in the database and persist across runs; the demo database holds two example presets; the dropdown shows "<name> *" while the view differs from the selected preset, until Save or Save as, and nothing prompts on exit or when switching presets). With no saved preset selected, the Graph opens with the demo's ten lines in the demo (including the four children's 529 balances, whose college years overlap), and in any other database with every aggregate asset (a user asset with an asset or rule member) in record order, else every account's default asset in record order; an empty database has no lines, and the first account added in the app gets these lines then. Edits and undo or redo in the app refresh the Graph without a reload. Changes made to the database by another process are picked up: the app checks the database's data version once a second and reloads when it changes. Click a line, its row or its data lane under the plot to select it, and hover over the plot for the crosshair and tooltip, with value tags in the y-axis gutter and the date tag below the plot. Below the plot and the lanes, the breakdown panel lists what changed the followed line over an interval, by cause, with Actual, Projected and Total columns and a closing Change row (end minus start); growth and shocks are split per market class ("Growth: <class>") and an Unexplained row appears when recorded balances are not explained by transactions. It follows the selected line (clicked on the plot, in its row or in its lane; its header has a dropdown to switch lines), else the first drawn line. On an aggregate line each cause row folds out to the asset's member accounts with each account's share of that cause over the same interval (transfers between members show in the member rows and cancel in the asset's total; a line that is a single account has no fold-out). Pan, zoom and fit gestures are unchanged; Shift-drag on the plot paints the interval as a tinted band whose edges can be dragged, and Esc (when no text field is active) or the panel's x button clears it. A set interval stays through panning, zooming and line changes; with none set the panel covers the 12 months ending at the cursor and follows the hover. The header shows the interval as two typed YYYY-MM-DD fields (first and last day, inclusive) and the quick choices Year at cursor, This year, Since start (earliest recorded data to today) and Next 10 years.

The Projections tab lists the projections as a tree with Reality first, with search, New, Clone, Rename and Delete, and edits a projection's parent, start date, override history, inflation, retirement date ("Retire on"), withdrawal order ("Draw from") and Roth conversion bracket, each inheriting when empty, and modifications (add, remove, edit a modification's kind, object, property, value and start in place, add and edit budget items, end a budget item on a date, drag to reorder; a How column makes a modification set or scale (Property and How are editable on every row except adds-item and adds-grant rows, also on a scheduled row, which keeps its segments and whose Value cell stays the Timeline button; making a scheduled row "ends on" ends it at its first segment's start and drops the schedule), with a scale entered as a percentage change such as -30, and budget items can have an annual raise; the Add form also has Shock and Rebalance kinds and a projection's shocks and rebalances are listed under its modifications with remove buttons (no in-place editing); modifications overwritten by later ones are greyed with a tooltip, and one whose target no longer exists is red with a tooltip and skipped). Edits are saved to the database at once. The Add forms for a modification, a budget item, an account and a start setting are disabled until valid and show their red reason only once something has been typed. Edit > Undo and Redo (Ctrl+Z, Ctrl+Shift+Z or Ctrl+Y, which do nothing while a popup or dialog is open) step through them until the database is reloaded. The Pin to Graph button pins the projection's lines on the Graph. An "Accounts in this projection" section adds, edits and removes the projection's own hypothetical accounts (inherited ones are read-only), and the modification target and budget-item account pickers list them. A "Start settings" section sets a start date and/or override history per asset (in order, drag to reorder, add and remove) and is followed by a table of the effective start of each account. Account and asset targets offer a default balance property (money in set mode, a percent change in scale mode), and the Add form has an optional To end date (an end without a start is refused); a modification with several segments (or a range) has a Timeline button that opens a timeline strip editor under the table, also used for a varying Inflation: drag segment edges (snapped to months, Ctrl for days) or type a segment's From and To dates (YYYY-MM-DD, taken exactly), split, delete, add and clear the end, each as one undo step.

The Assets tab shows a tree of the user's assets (aggregates) with their members nested (accounts, assets and rule members read like "Rule: all accounts, 12 accounts" with the full match list in a tooltip) and today's balance for each; an account's default asset is not listed. A member that would count an account already counted is drawn red with a tooltip naming the duplicates and the earlier member. The selected asset has a small chart of actual (solid), projected (dashed) and default (faded) values from about a year back to 10 years ahead, with the Graph's hover crosshair (value and date tags), pan and zoom (drag, scroll; double-click or selecting another asset refits), and a coverage bar below it, its "Actual data" label on its own line and the bar following the plot's x range, showing where its members have actual data and the last actual date. The name is edited in place; an Add member form (account, asset or rule, the rule's pickers labelled "Accounts of type" and "with tax treatment", "any" when none is ticked; a rule never changes the accounts it picks, and shows as e.g. "Rule: accounts of type Checking with tax treatment Taxable" or "Rule: all accounts") and a New asset form are disabled until valid, with a red reason shown once something has been entered; Delete opens a confirmation dialog that lists what refers to the asset (other assets' members, projection asset settings and modifications for it) and that is removed with it; it is disabled, with the reason, for an account's default asset. Accounts under the asset stay, with their modifications. Edits can be undone with Edit > Undo. A rule member is live: an account added later that matches joins the asset. Asset and account names must be unique (ignoring case and surrounding space), else the edit is refused (`name_taken` on the command line): an asset's name may not equal a record account's name or any projection account's name, and a new or renamed account may not take an asset's name (record and projection accounts may share names). The delete dialog also lists each saved view preset that loses lines; deleting removes the asset's lines and the bands using them from those presets, and the presets stay. Undo restores the preset lines and redo removes them again; a preset changed since is left as it is, with a notice naming it. The detail pane also has a Default balance section (the intervals in the order they apply, a later one winning where they overlap; edit a value or dates in place, remove, drag to reorder, and an Add form disabled until valid, its red reason shown once something has been entered) and a Parameters section (growth: none, a constant edited in place with Set, or a schedule; a Timeline button, shown once a setting exists, opens a timeline strip editor; Clear removes the setting). An Effective growth table lists each member account's layers in apply order (the account's stated rate, then each asset along the path that sets growth, the later winning on the dates it covers; a layer overwritten today is greyed) and the effective value today. A growth schedule with no segments is refused ("a growth schedule needs at least one segment"); an empty one already stored counts as no setting.

The Accounts tab lists the accounts grouped by type (each group of more than one account has a tinted header row reading "<title> · <count> · <subtotal>", the subtotal in whole dollars, with its accounts indented under it, and a group of one account has no header and no indent; an equity account's Tax cell is blank; while an account's ledger is open the list drops its Tax column so names show in full) with each one's balance, the date of its last data and a stale flag (an open account whose last data is more than 45 days old), and closed accounts apart. An Add account form (disabled until valid, its red reason shown once something has been entered) adds a manual account; the selected account's name, type, tax treatment and stated rate are edited in place (a 529 also has a College savings section with its beneficiary, picked from the household's dependents, and its contribution basis; a mortgage also shows its terms: original amount, term in months, first payment and paying account, with the monthly payment worked out once all four are set; a credit card's rate compounds daily while it owes money); a Record a balance form adds a snapshot; the default balance intervals are listed with remove and add. Close (with a date), Reopen and Delete are offered. A Household section at the bottom of the list panel edits the household's members, filing status, state table and reconciliation account. Each earner and spouse has a collapsible Benefits section there with their Social Security inputs (the monthly benefit at full retirement age in today's dollars and the claim age, 62 to 70) edited in place, and their FERS inputs (high-3 salary, years of service, separation age, annuity start age and survivor option) edited in place, or, for a member without FERS, an Add FERS form (disabled until valid, with its red reason) and, for one with it, a Remove FERS button. Delete opens a confirmation dialog (Delete or Cancel) that lists what the delete changes: the account's membership in other assets, the employer matches into it and the mortgage terms paid from it (both cleared), projection asset settings and modifications for it or its default asset, and the base and projection-added budget items that move money in or out of it, with the modifications of them. An account with record entries, or one that is the counter account of any entry, is never deleted: the dialog says so and offers Close account (disabled, with a red reason, while the Closes-on date is invalid) or Cancel. A closed account keeps its history, reads 0 after its close date, stops its budget items after that date, is left out of the pickers for new Graph lines, modification targets and budget-item accounts, and refuses entries dated after the close date. Account and asset edits, including a delete with everything it changed, can be undone with Edit > Undo in one step, except recording entries, which is append-only. A Record a transaction form (date, amount, kind, a Transfer account picker, shown only for a transfer, that leaves out the account itself and closed accounts, memo; a transaction of any other kind is saved with no transfer account) sits beside the Record a balance form and is disabled until valid, its red reason shown once something has been entered. The account's record entries are not listed inline: an Entries (N) >> button in the detail folds a ledger panel out to the right of the detail (the button then reads Entries (N) <<), N being the number of entries listed. The panel is closed by default, stays open when another account is selected, is not stored, and is not drawn with no account selected. It holds a Show voided checkbox (voided entries are included, marked voided; with it off the tab says how many are hidden, and N follows it, and the selected entry's editor closes if that entry is no longer listed), the entries newest first (date descending, same-day ties newest-recorded first) in a scrolling table with date, kind (snapshot, income, expense or transfer), amount or balance, transfer account and memo, and below it the selected entry's editor: a Correct form prefilled with its current values and a note, a Void button with a note (for a voided entry, Restore instead: a correction that changes no value) and a history table of every revision with the time made (local), note and voided marker. With the panel open the three columns share the width: the ledger keeps at least 40 font sizes, the detail shrinks first, then the list; the Add account form stacks its fields one per line when the list is narrow. Adding, correcting, voiding and restoring entries push no undo step (recording a vest of an equity account is the exception, see below).

The Budget tab shows the base budget's items as one aligned table with a single header row (Name, Repeats, Amount, Accounts, Taxed as, Starts, Ends, Indexed, Growth, Per month), grouped as Income, Expense and Transfer under tinted group rows (an empty group reads "No income items." and so on), each row with name, schedule, amount, accounts, start, end, indexed, annual raise and monthly equivalent. Above them are the monthly income, expenses and amount left over as of the record's today, in today's dollars (transfers are in neither; a one-time item counts for nothing and an annual one for a twelfth). Edit opens an item's fields in place (the Projections tab's item fields plus a "rises with inflation" checkbox), with an End date; each row has a disclosure arrow that opens or closes the editor and a trash-can icon (tooltip "Delete") that opens a confirmation naming the item and listing the projection modifications that would be left pointing at nothing (red, and skipped, on the Projections tab); confirming deletes it and can be undone; an Add form is disabled until valid, with its red reason shown once something has been typed. The table has a hint that a dash means no start or end date is set; the item amount shows thousands separators and keeps cents when present ($5,000, $1,234.50), an expense paid from a 529 account shows "(college cost)" after the account, and the per-month column is written the same way, without "a month". The GUI shows account types, tax treatments and item kinds by display names (Checking, Credit card, 401(k), Roth IRA; Taxable, Tax-deferred; Income, Expense, Transfer); stored values and the command line's output keep the raw strings. Income items have a "taxed as" choice (wages, ordinary income or tax-free) in the forms; a wages item also has an employer match: "employer matches" a percent "of contributions up to" a percent of pay, into a chosen 401(k) or TSP account (or no match). Every repeat can be set in the forms: a picker (without a "repeats" label) offers Weekly, Biweekly (every 2 weeks), Semimonthly (twice a month, on two chosen days), Monthly (a day 29 to 31 falls on the last day of a shorter month), Quarterly, Annually, One-time and Custom (every N days, weeks, months or years), each with a plain-meaning hint, and every kind has a start date, an optional until date and an optional raise per year. The start defaults to today, except that a one-time or biweekly item uses its date as its anchor. Switching an item's repeat in place fills sensible defaults (Custom 2 weeks, Semimonthly the 1st and 15th, Monthly and Annually the day and month of the date, else the 1st and January), and edits to other fields never flatten a schedule or change a start. In the in-place editors (here and for an added item on the Projections tab) amount and raise each have a "timeline" button that opens the timeline strip on that schedule; one that already changes over time shows its value now and "changes over time" instead of a number field. The Add forms take single numbers. Edits can be undone with Edit > Undo. The tab has two views, Items (the table and Add form above) and Taxes. The Taxes view shows one year's tax as the engine books it, for Reality or a projection (the Projection picker lists Reality and each projection and defaults to the first projection) and a year (the - and + buttons step it, This year returns to the record's today year, which is the default). Its rows are wages, RSU vests, other income (interest noted), Social Security received (when not zero, with the taxable part noted), early withdrawals (when not zero), non-qualified 529 earnings (when not zero), realized gains (when not zero, short-term and long-term noted), pre-tax deductions (what the tax rules deducted after the limits, with the contributed 401k, IRA and HSA noted), adjusted gross income, federal taxable income, federal tax before credits, credits, state taxable income and state tax (labelled with the household's state), FICA (Social Security and Medicare noted), net investment income tax, tax on realized gains and early-withdrawal penalty (when not zero), total tax, withheld, and owed or refunded with the reconciliation date and account. A Tax tables... toggle beside Household... shows the tax tables editor below the view (also when the year cannot be computed): pick Federal or a state table, a year the table has and a filing status (defaulting to the household's state, the household's filing status and the view's year), and edit the bracket rows (Over threshold and rate in percent; the first row's Over is fixed at 0 and cannot be removed; each other row has a remove button; an Add row adds one), the standard deduction, the federal credits, rates, Social Security wage base, thresholds (including the two long-term capital gains thresholds and the two Social Security benefit taxation thresholds) and 401(k), IRA and HSA limits, or the state's exemption per filer and dependent and 529 deduction cap. Each edit replaces the whole table as one undo step and a refusal shows beside the field; a state standard deduction of 0 removes that filing status's entry. Where the shipped table has a different value the field shows it with a Revert, the brackets show the shipped list with a Revert, and a Revert table button appears while the table differs from the shipped one; a state table the program does not ship shows none of these. Use for household makes a state table other than the household's the household's. The New state table form (name, the table to copy, Create) adds a state as a copy of every year of another, to edit and then pick in the household. A year the engine cannot compute shows its error, and the engine's notes and any skipped modifications show as text below. The Household... button opens the Accounts tab with the household editor scrolled into view. The selection follows a renamed projection and falls back to the first projection if it is deleted. The same figures are on the command line as `tax year`. Comparing actual spending with the budget is not built yet.

The Markets tab lists the market classes with their expected return per year and volatility, edited in place (a class whose return is not one constant rate shows "varies", read-only), and a correlation matrix whose cells above the diagonal are edited in place (-1 to 1; 0 removes the pair). Selecting a class shows its name editor, its projection overrides (read-only; the growth modifications and shocks that projections hold on it, edited on the Projections tab) and the accounts exposed to it: Account, Balance, Target (allocation percent), Share (actual percent) and Amount (the account's balance in the class today), with a total; accounts with no balance today are omitted. Classes are added and removed with `class add` and `class remove`. The Accounts tab's detail for an investable account has an allocation editor: a percent per class with a sum line, Set allocation (disabled with a reason while the percents are invalid), Use default, Clear and a yearly-rebalance checkbox. Class, correlation and allocation edits can be undone.

## Screenshot

    bin/finplan [--demo] --screenshot <out.png> [--tab <name>] [--frames N] [--size WxH] [--select <name>] [--open <state>] [--check-ids]

Screenshot mode lets the GUI be inspected without a person at the window. It draws `--frames` frames (default 10) without waiting for input, reads the last frame back from the framebuffer, writes it to `<out.png>` at the framebuffer's pixel size and exits 0; any failure exits non-zero with a message.

- `--tab <name>` is the tab to show: Graph (the default), Projections, Assets, Accounts, Budget or Markets; the name is case-insensitive.
- `--size WxH` is the window size in pixels (default `1280x800`).
- `--select <name>` selects the projection, asset, account or market class of that name, and works only with the Projections, Assets, Accounts, Graph and Markets tabs. On the Markets tab it takes a market class's name. On the Graph tab it takes a projection: the equity accounts and the brokerage accounts their grants deposit into are added as lines and the projection is shown, as the Projections tab's Show on graph does. On the Assets tab an account's default asset is not listed and cannot be selected. An unknown name is an error.
- `--open <state>` shows a state open: `add-line` (the Graph tab's Add line picker), `breakdown-line` (the Graph tab with the Net worth line selected so the breakdown panel follows it; use `--select <projection>`), `breakdown-interval` (the same with the interval set to the calendar year before today) and `breakdown-expand` (the same with the first cause row folded out to its member accounts), `monte-carlo` (the Graph tab with Monte Carlo on for the Net worth line, which is soloed; use `--select <projection>`, e.g. Base; the screenshot waits up to 15 s for the background runs), `about` (the Help > About finplan dialog, on any tab), `target` (a Projections tab target picker, which needs `--select <projection>`), `member` (the Assets tab's member picker, which needs `--select <asset>`), `new-item` (the Projections tab's Add form for a new budget item, which needs `--select <projection>`), `focal-grant` (the Projections tab's Add form on the focal grant kind, which needs `--select <projection>`), `budget-item` (the Budget tab with the first item's editor open), `budget-delete` (the Budget tab with the confirmation for deleting the first item), `shock` and `rebalance` (the Projections tab's Add form on the Shock or Rebalance kind, which need `--select <projection>`), `budget-taxes` (the Budget tab with the Taxes view), `tax-tables` and `tax-tables-federal` (the Budget tab with the Taxes view's tax tables editor shown, on the household's state table or on the federal table), `member-form` (the Assets tab's Add member form without the picker, which needs `--select <asset>`), `timeline` (the Projections tab's timeline strip editor for the projection's first modification with a schedule, segment 1 selected, which needs `--select <projection>`) or `asset-timeline` (the Assets tab's timeline strip editor for the asset's growth, segment 1 selected, which needs `--select <asset>` and an asset with growth, such as the demo's 529 accounts; it writes nothing), `asset-delete` (the Assets tab's delete dialog for the selected asset, which needs `--select <asset>`), `account-delete` (the Accounts tab's delete dialog, which needs `--select <account>` (with `--demo` the account added next is opened instead); with `--demo` it first adds an account "Brokerage 2" with no entries and a view preset "Brokerage 2 view" showing it, so the dialog lists a preset; with `--db` it creates nothing) `ledger` (the Accounts tab with the selected account's ledger panel folded out, which needs `--select <account>`), `member-benefits` (the Accounts tab with the household editor scrolled into view and each member's Benefits section folded out) or, all on the Accounts tab and needing `--select <equity account>` such as `--select "Acme RSUs"`, `equity-grants` (the Grants section), `equity-add-grant` (the Add grant form), `equity-schedule` (a grant's schedule), `equity-vest` (the Record vest form), `equity-tie` (the Record vest form tying to an existing deposit), `equity-move` (the Move date form of a planned vest), `equity-correct` (a grant's untouched Correct or void form), `equity-prices` (the Prices section) and `equity-calendar` (the Vest calendars section). It is an error for an unknown state or with a tab other than the one named. The add-line and target lists are scrolled so the boundary between accounts and assets is in view.
- `--check-ids` finds widget ID conflicts. After the PNG is written, a synthetic mouse visits a grid of points, one per frame, and reads ImGui's count of items sharing the hovered ID; any point where more than one item shares it is reported as a widget ID conflict (ID, position and window) and the process exits non-zero. The scan does not scroll: it makes a virtual display as tall as the windows' overflow needs (up to a cap), so content below the fold is reached, and fails naming a window still clipped at the cap; popups, menu bars and the Accounts tab's entries table (which draws only its visible rows and scrolls by design) are exempt and logged, and what is below the table's scroll range is not scanned. The PNG and its size are unaffected. The grid step is based on the font size, so it can miss the 10 px timeline drag handles; items behind an open popup are not hovered, so the forms behind a picker are scanned with `--open member-form` and similar states. The scan fails with a clear error past its frame bound or its 20 s wall-clock bound.
- Each of `--tab`, `--frames`, `--size`, `--select`, `--open` and `--check-ids` is an error without `--screenshot`.

If `SDL_VIDEO_DRIVER` is unset and neither `DISPLAY` nor `WAYLAND_DISPLAY` is set, screenshot mode sets `SDL_VIDEO_DRIVER=offscreen` itself; it can also be set explicitly, which needs no display server (OpenGL still needs a driver, such as Mesa's software one):

    SDL_VIDEO_DRIVER=offscreen bin/finplan --demo --screenshot /tmp/accounts.png --tab Accounts

## Command line

    bin/finplan [--demo | --db <path>] <command> [arguments] [flags]

With no command (`finplan` or `finplan --demo`) the app opens its window as above. With a command, the same binary reads or writes the database and prints one JSON document on stdout, without a window. Run `bin/finplan help` for the commands and `bin/finplan help --json` for the same description as JSON, generated from the command definitions the parser uses.

- `--demo` (a throwaway seeded database, removed on exit) and `--db <path>` work on every command, before or after it; using both is a usage error. With neither, the real database is used (same location as the app).
- Read commands never write: they open the database read-only. A missing file is an error (`no_database`) and is not created. A database older than the program gives `old_schema` (open it with the app first so it is upgraded), and a newer one `future_schema`.
- Errors are `{"error":{"code","message"}}` on stdout, with exit code 2 for usage errors and 1 for all others. Codes: `usage`, `not_found`, `ambiguous`, `no_database`, `old_schema`, `future_schema`, `database`, `engine`, and for the write commands `unknown_target`, `name_taken` (a name that clashes with another asset or account, ignoring case and surrounding spaces: an asset may not take the name of a record account or of any projection's account, and an account may not take the name of an asset; record and projection accounts may share names; data that already clashes still loads and edits that keep the name are allowed), `has_children`, `cycle`, `invalid`, `in_use` (deleting an account that has record entries or is the counter account of one: close it instead; or removing an account from a projection while a modification, item or asset setting of the projection or one building on it uses it), `failed` (any other error; exit 1), `confirm_required` (a delete that changes other objects and was not given `--force`; the error also has `affected`) and `record_changed` (the record changed since it was loaded). `not_found` also covers unknown assets, accounts and entries.
- Dates are `YYYY-MM-DD`, and `null` when absent or unbounded. Statuses are lowercase: `default`, `actual`, `projected`, `partly_projected`. Reality appears as `"projection": null`.

Read commands:

Commands about data that belongs to one kind of object are noun-verb (`account list`, `projection show`). The engine queries (`balance`, `breakdown`, `starts`) are top-level verbs because they accept either an asset or an account.

A `<target>` is an asset or account given by id or display name; ids win over names, an account and its default asset count as one object, and a name matching several objects is an `ambiguous` error. `--from` and `--to` take `YYYY-MM-DD` or `YYYY-MM`: for `--from` a month means its first day, for `--to` its last day. Month and year steps keep the day of month of `--from`, clamped to the end of shorter months.

Write commands go through the same edit operations (`internal/ops`) as the app, so both agree on what an edit may do. Details:

- Database: `--demo`, `--db` and the default work as for reads, but a write command opens the database with `store.Open`, so it migrates an older database, and still never creates a missing one (`no_database`). A `--dry-run` never migrates: against a database that needs it, it is refused with `old_schema` (exit 1); run the command without `--dry-run`, or open the app, to upgrade it first. Read commands still never write.
- `--dry-run` (every write command) applies the edit to a copy, runs the same checks as a real write (including that the record could be saved and restored), prints what would change and saves nothing.
- Output of the projection commands is `{"dry_run","changed","projection"}`, the projection in the same shape as `projection show`, after the edit. The asset, account, entry and budget commands print `{"dry_run","changed",<object>}` with `asset`, `account`, `entry` or `item` in the shape its read command prints (`asset delete` and `account delete` add `removed` and `affected`, a list of `{kind, in, detail, effect}`, where a saved view preset that loses lines is listed with kind `view preset`, its name in `in` and the number of lines and bands in `detail`, `entry void` adds `voided`; `account new` also prints its default `asset`); an entry added in a dry run has `id` null. An edit that changes nothing prints `"changed": false` and exits 0. `projection rename` adds `renamed` (`{from,to}`, or null), `rewritten_presets` and `warnings` (presets that could not be rewritten; the rename is saved regardless). `projection delete` prints `removed` and the projection as it was.
- Projection accounts: `projection add-account` needs `--name`, `--type`, `--tax` and `--from`; `--id` is made from the name when omitted and must differ from every account and asset id and from the accounts of the projection's chain and descendants (siblings may reuse an id). The account exists under that projection and the ones building on it, reads 0 (no data) before `--from`, is `--opening` on that day and grows at `--rate` from then. Balance, breakdown and starts accept it under `--projection`, as do `mod --target account:`, and `item --account/--from/--to`. A breakdown over the opening date has an `opening` line. An item that touches such an account counts, on every side, only after the latest of its accounts' cutoffs, so a transfer's two sides agree. To model buying a house: add the home as a `property` account (price as `--opening`, appreciation as `--rate`) and the mortgage as a `mortgage` account (negative `--opening`, interest as `--rate`), both `--from` the purchase date; add the down payment as a one-time transfer from checking to `outside`, and the monthly payment as a transfer from checking to the mortgage. A projection account has no mortgage terms, so this mortgage is not amortized; the payment is the transfer.
- Rates (growth, inflation) are fractions: `0.03` is 3%. A negative rate given as an argument needs `--` before it.
- Modification values are a constant (`--value`, from `--from` to the inclusive `--end`, always and open-ended when omitted; `--end` without `--value` and `--from` is a usage error) or a schedule read as JSON on stdin or from `--json-file`: `[{"from":"YYYY-MM-DD","end":"YYYY-MM-DD" or null,"value":number}]`, sorted and not overlapping. A `from` of `null` (or an absent one) means from the beginning, which is how `projection show` prints a schedule that starts at the beginning, so its output can be written back; an empty list is the empty schedule. Input is decoded strictly: unknown fields and trailing data are usage errors.
- Budget items: `--kind income|expense|transfer`, `--name`, `--amount` (above zero), `--every one-time|weekly|biweekly|semimonthly|monthly|quarterly|annually|custom` (`annual` also works), `--start <date>` (`--on` is the same; give one), `--day` (monthly, semimonthly), `--day2` (semimonthly), `--count` and `--unit days|weeks|months|years` (custom), `--end <date|none>`, `--account` (income, expense), `--from` and `--to` (transfer), `--indexed`, `--growth` (annual raise as a fraction, 0.03 for 3%) and for `item add` `--id`. Or give the item as JSON (the shape `budget list` prints) on stdin or `--json-file` instead of the flags. A new item needs a start; days 29 to 31 fall on the last day of shorter months; an annual item's day is checked against its month; weekly, biweekly, quarterly and custom repeats count from the start (or the recurrence anchor in JSON). A one-time item happens on its date (the recurrence anchor); a start, if given, must equal it, otherwise the write is refused (`invalid`). `--amount` and `--growth` take one number; for amounts or raises that change over time give the item as JSON, where `amount` and `growth` are a number or `[{"from","end","value"}]` (the `budget list` output adds `amount_schedule` and `growth_schedule`, and a number given with a schedule must equal its value today). An edit without a date flag keeps the start. The id is made from the name (a unique slug) when not given. An item is stored as an add_item modification. `item end` appends an amount modification with value 0 from the date.
- Targets are checked by the shared operations: the property must suit the target (amount or growth for an item, growth for an account or asset or stock or class, inflation for global, add_grant for an equity account), and the target must exist at the modification's position, else `unknown_target`: a record budget item, an item added by an ancestor projection, or an item added by an earlier row of the same projection. `mod add` cannot add an item (use `item add`). A move, removal, parent change or removal of an added item is refused if a modification that resolved before would no longer resolve; modifications already dangling do not block an edit.
- Assets: a member that overlaps an earlier one is never refused; the later member is listed under `invalid`. An account's default asset (`acct:<id>`) cannot be renamed, deleted or have members changed. `asset remove-member` and `asset delete` renumber the members' seqs 1..N in order, so later seqs can shift. On a default asset, `add-default` and `remove-default` change the account's own default balance and `set-param` its settings.
- Equity: an equity account's balance is derived from its grants (unvested shares times the latest price observation on or before the date, the grant price before any); `entry add-snapshot` refuses an equity account, and one with no grants still reads legacy snapshots. An account with grants, or one that is a grant's brokerage account, cannot change type or be deleted. The demo data has an equity account `equity` ("Acme RSUs", ticker ACME) with two grants, recorded vests and prices. The Accounts tab shows an equity account's detail with Grants, Add grant, Prices and Vest calendars sections in place of Record a balance: the grants with their vested and unvested shares and unvested value at the latest price; an Add grant form with a live preview of the derived shares and per-vest schedule; a grant's schedule (planned and recorded vests, with per-vest percents editable while no vest is recorded), Correct and Void (a grant with recorded vests cannot be voided); Record vest from a planned row, either recording the brokerage deposit or tying to an existing unmatched deposit; prices; and calendars. Recording a vest is one undo step (undo voids the vest and the deposit and price observation it created); other equity edits are facts that are corrected or voided, and calendar edits are undoable. Projections model the equity account: its balance is its unvested shares times the stock's projected price (the latest price on or before the projection's start, grown by the stock's growth and the projection's `stock` modifications), each unrecorded planned vest after the start moves its net proceeds to the grant's brokerage account and its withholding leaves as tax, and focal grants add planned grants. The demo has projections "Acme +15%", "Acme crash" (a 40% drop over the year from 2027-06-01) and "Acme yearly grants" (an $80,000 grant every March from 2027). Its "Crash and rebalance" projection (built on Base) rebalances the brokerage to 60/40 large cap and bonds on 2027-02-01, which sells shares at a short-term gain taxed in 2027, then applies a -40% large cap shock on 2027-03-02. Its "Retire at 60" projection (built on Base) retires on 2045-03-12 and converts to Roth each year up to the top of the 22% bracket; the household draws on its accounts from then and money does not run out.
- Record: entries are never edited in place. A snapshot on a date that already has one is refused (use `entry correct`); `entry correct` and `entry void` go through the store's corrections, and their dry run runs the same checks in a rolled-back transaction. A transfer needs a counter account that exists and is not the account itself. The stated rate is limited to -1..1.
- Base budget: `budget end` sets the item's end date and refuses one before the start. Semimonthly items can be created (with `--day` and `--day2`), edited and ended.
- Exit codes and error codes are as above: `usage` exits 2; `not_found`, `unknown_target`, `name_taken`, `has_children`, `cycle`, `invalid`, `in_use`, `record_changed`, `database`, `no_database`, `old_schema`, `future_schema`, `ambiguous` and `failed` exit 1.

Run `bin/finplan help --json` for every command's arguments, flags (with types), whether it writes and what JSON input it reads.
